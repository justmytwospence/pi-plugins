# Remote client compatibility

Maintainer rules for keeping the suite's dialogs, footer and below-editor widgets readable by the phone clients that parse Pi's screen. The public overview is `site/src/content/docs/guides/clients.md`.

## Sidebar family views

Planner and subagent views compose in Sidebar's primary pane. Closing Sidebar expands the current view; closing the primary view returns to main with Sidebar still open. Native dialogs temporarily suspend the split and restore the prior view and focus. Sidebar is read-only; primary-view human controls are unchanged. Its roster covers explicitly enrolled family members, not unrelated same-directory or same-machine sessions, and can report partial or unavailable coverage.

Changes to this composition require real-renderer coverage at 46, 120 and 180 columns, including navigation, resize, mouse, editors, dialogs and draft/focus restoration, and `npm run check:clients`. Check both clients for false composer/send targets as well as dialog parsing; do not add exceptions or claim validation before those checks pass.

## herdr-web-ui compatibility

herdr-web-ui (devswha/herdr-web-ui, `server/prompt.ts`) turns a waiting Pi dialog into a phone card by reading the screen text. It has no configuration hook for dialogs. Every dialog that holds `herdr:blocked` must keep a layout it can read, or phones fall back to a bare Enter/Esc card:

- **Pi layout** (single-choice questions, tool-gate approvals, plan approval, Review): from the bottom, at most 2 footer lines, a rule, then Pi's key hint ending in `↑↓ navigate  enter select  escape/ctrl+c cancel` (or `enter submit  escape/ctrl+c cancel` under a single `›` input line). Above that a blank line, then one row per option (cursor `→`, single-space labels, cursor on the first row). A wrapped rest of a row goes behind a 1-column `│`. Above that a blank line, then the question.
- **OmO form** (multi-select questions): an `Ask user` line (here the dialog's titled top border; anything after `Ask user` must follow a ` · `), a tab bar ending in `Submit`, numbered rows indented 2-4, an unnumbered `Type your own answer` line, and a hint starting `↑↓ move  1-9 select  space toggle  enter next` and ending `esc cancel`. No footer line may end in `%`, `$`, `#` or `>`. Number keys toggle, Backspace clears, Tab commits.
- Message delivery follows herdr's pane status: herdr-web-ui queues or holds a chat message (Send now) while the pane is `working`. pi-bg keeps a turn open while it waits on a job (`bg_wait`, or the wait at the turn's end), where typing in the terminal ends the wait. It holds `herdr:waiting` meanwhile, and pi-herdr publishes the pane token `wait`. Spencer's fork reads it with `HERDR_WEB_WAIT_TOKEN=wait` (homelab `herdr-web`): it types the message at once and its chat says `Waiting on …`. Any new way of keeping a turn open only to wait should hold `herdr:waiting` too.
- pi-status-footer normally shows separate Workflow and Approvals rows when their providers exist, including during exec. It shrinks to one row while `herdr:blocked` is held, retaining the workflow badge when available alongside project, branch, model, reasoning, context and any active phase; at narrow widths the badge and phase take priority and other details may shorten or disappear. A pi-bg or subagent activity row still fits in the 2 lines after the hint. Keep `/mode` and `/approvals` picker options short.
- Anything drawn on an option row shows up in the phone card's option text, so keep box glyphs and decorations off unchecked rows.

Before changing a dialog's rendering, the footer, or below-editor widgets, render the screen at 46 and 120 columns. Feed it, plus the footer and any activity row, to the installed parser: `parseInteractivePrompt("pi", screen)` from `~/.local/share/herdr-web-ui/remote-v*/server/prompt.ts`, run with that bundle's `bin/bun`. Check the card's question, options and `multi_select`, and the text-box card after "Type something." or "Other". Re-check after herdr-web-ui updates. `npm run check:clients` does this for every dialog.

## Collie compatibility

Collie (AltanS/collie) also reads a waiting Pi dialog off the screen, and finds the editor by its frame to decide whether a phone send may type. Out of the box it reads vanilla Pi only, so everything the suite draws differently is declared to it in `~/.config/collie/frames.toml`, managed in dotfiles (`home/dot_config/collie/frames.toml`): pi-status-footer's `━` gauge in the editor rules and its indented footer, pi-vim's mode label at the bottom rule's end, pi-bg's activity row and the blank row under it, the `│` gutter of a wrapped option, the multiple choice's `✓` tick column and `Other` row, and pi-sidebar's dividers (`panel_below`, `panel_beside`), so Collie reads only main's side of the split. That file needs a Collie build with `frames.toml` support: until upstream ships it, the fork branch `justmytwospence/collie` `feat/pi-frames`.

- The dialog layouts above serve Collie too: single-choice questions, tool-gate approvals and Pi's own selects lift as walked buttons; a lone multiple choice lifts as checkboxes (its digits toggle, `tab done` submits, `Other` stays in the terminal), and several questions at once show Collie's Escape card. Keep those shapes inside `frames.toml`'s declarations, or change the file with them.
- Native tree pickers, including `/tree-fork`, and pi-history-search's searchable prompt-history picker remain terminal-operated. The compact history picker temporarily replaces the native prompt area using ordinary `ctx.ui.custom`, not an overlay. The conversation stays above it, with the footer/activity rows and Sidebar outside the replaced editor dock. It uses the prompt area's width, normally shows up to eight results, and renders at most 13 rows without blank padding. Cancellation preserves full draft text, but native restoration may reset cursor/undo and expand collapsed pastes. Ctrl+R remains Vim redo in Normal mode; search makes no model calls. The history picker's filter input belongs to the terminal, not a remote prompt composer; it does not hold `herdr:blocked` or ask a model question. Collie's whole-pane `unread-dialog` mirror with its declared Escape-only control is expected, not a parsed option list; it must not expose an editable composer. `check:clients` verifies this precise mirror or raw output for both default and All tree filters and initial, filtered, no-match and long/Unicode prompt history, not arbitrary unread question dialogs. The real ordinary-custom editor-container fixture checks these history states at 46/120/180 columns over blocked and normal footers (including the 13-row status allowance), with and without activity rows and with Sidebar absent, collapsed or expanded. It checks compactness and conversation visibility while open, then native editor/focus restoration and the idle draft composer after closing.
- Herdr-web-ui parses Pi's picker with the cursor on its initial first row; a cursor moved by hand does not create a fresh card. Its answer route navigates from the parsed card and verifies the moved row. Client fixtures for Save for later use the parser's `answerKeys` to select that row, not a new parse after moving it. The filename form uses a real prefilled Pi Input: the phone card still calls its text option `Type your answer`, and custom answers clear the existing value with Ctrl+K/Ctrl+U before typing. The plan-review scroll handler must release Ctrl+U while that input is open.
- Pi's own select (`ctx.ui.select`, which pi-cache-guard's questions, plan approval and compact-plan use) wraps a long option onto the next row without the `│` gutter, and Collie reads no dialog that has one. So every option of a select that holds `herdr:blocked` fits 42 characters (the 46-column phone width less the cursor and padding; pi-cache-guard's `OPTION_MAX`). Put counts, costs and reasons in the question, which may wrap, not in the options. `check:clients` fails when a checked select's option would wrap.
- A change to the editor's rules, the footer's height or indent, or a below-editor widget must stay inside `frames.toml`'s limits, or change that file with it (and restart Collie). The two-axis normal footer requires a `status_rows` allowance of 13. That limit bounds the whole region below the editor, including any activity pill and its blank separator, not only the footer. `status_blank_rows` permits a separator within that region; it does not extend the row budget. The maximum-status fixture therefore uses eight notebook rows without a pill, or six with a pill and separator, alongside the five core footer rows.
- tool-gate's approval rows are short (`Allow rule for this session`, `Allow rule in this project`, `Allow rule everywhere`, `Edit the rule...`); managed globals omit the everywhere choice. The question names the local or shared project destination and contains each rule or folder on a flat `Rule: ...` or `Folder: ...` line. Keep those question lines flat: a header with an indented list under it (`Rules:` then indented rows) makes Collie read no dialog. The open `›` field (Block with a message, Edit the rule) reads as a text box in herdr-web-ui; `check:clients` does not draw it, and Collie shows its Escape card there.

`npm run check:clients` renders every dialog at 46 and 120 columns over the blocked footer and runs both clients' readers on it (herdr-web-ui's installed bundle, and a Collie checkout at `~/Projects/collie` with this machine's `frames.toml`); a client that is not installed is skipped. It also draws every dialog with pi-sidebar open (collapsed, as it is while a dialog waits) and main's idle editor with Sidebar open, which must read as it does without Sidebar (Collie reads only main's side of the split through `frames.toml`'s `panel_below` and `panel_beside`). Run it after changing a dialog, the footer, a below-editor widget or Sidebar's layout.

A screen a client misreads is fixed, not excused: in the suite's rendering, in `frames.toml`, or in the Collie fork (`justmytwospence/collie`, a patch stack; see the global `fork-patch-stack` skill). `check:clients` has no exception list for new work; a change is not finished while it prints `FAIL` or `KNOWN`.
